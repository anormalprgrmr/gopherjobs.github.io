THE OPPORTUNITY NavVis builds mobile mapping systems, with hardware and software designed and manufactured in Munich.

The System Software runs onboard our devices such as NavVis VLX, NavVis MLX and NavVis CLX. It runs our proven SLAM for survey-grade point cloud quality and features a UI that lets you intuitively control the device and the capturing process. Live feedback displays the scanning coverage and progress to ensure dense, high-quality scanning.

We are looking for a Senior Linux Platform Engineer for the System Software team in the Mapping and Perception (MAP) department. You own the Linux platform including the OS lifecycle, system services, patches and modifications to system libraries, graphics, and media integration. This is a platform and integration role: you do not write bootloader code or firmware.

You work with the application and UI people and at the kernel and userspace boundary, in close cooperation with the Embedded Software team, which owns the bootloader, kernel drivers, and firmware beneath you. The mission of the System Software team is to continuously improve the application with new features and better user experience while shipping the full software that runs on our devices multiple times a quarter.

This role requires at least 3 days of office presence per week. How You Will Make An Impact

  • Own the application and OS lifecycle: build, adapt, package and release Debian and Ubuntu images on amd64 and ARM, including OS updates, migrations, build and release pipelines, dual-boot, and over-the-air update mechanisms that scale with production volumes
  • Integrate drivers into application code: work closely with the Embedded Software team and bring in modifications and kernel patches, collaborate on the hardware abstraction layer, and integrate drivers with applications
  • Support the ROS-based mapping stack: collaborate with your teammates on the C++ and Python-based application, the mapping stack and its ROS nodes
  • Patch and integrate system libraries: adapt, modify and maintain system libraries that need device-specific adaptations (e.g. Mesa/OpenGL, libc) to ensure the software can make use of the full capabilities of the hardware.
  • Develop sensor software modules, own the camera and media userspace: ranging from V4L2 interface, image formats and controls to LiDAR scanners and other sensors, building on top of kernel drivers delivered by the Embedded Software team
  • Keep quality measurable: build and maintain CI pipelines, hardware-in-the-loop tests, and stress tests and performance benchmarks and more.

What Will Help You Succeed In The Role

  • 5+ years building and shipping software for Linux-based devices at the OS and userspace level (images, packaging, system services), ideally on ARM-based platforms
  • Strong hands-on C++ experience in a production codebase and solid Python for tooling, scripting, and automation
  • Hands-on Linux image building and OS lifecycle management: Debian or Ubuntu image builds, packaging, update or OTA mechanisms, and reproducible, tested build pipelines
  • Linux userspace platform experience: system daemons, D-Bus or comparable IPC, systemd, packaging, and platform tooling
  • Fluency at the kernel and userspace boundary: reading kernel code, applying and carrying kernel patches, working with sysfs and udev, and debugging across the boundary in the field
  • Integration experience in at least one of: V4L2 and camera and media pipelines; GPU or graphics stacks and kernel-dependent libraries (OpenGL, Vulkan, libc, vendor blobs); or GNSS and sensor protocol software (message parsing, forwarding, timestamping)
  • Clear and fluent communication in English

Would be an added benefit

  • Familiarity with ROS or comparable robotics middleware in a production environment
  • Experience with camera systems and sensors
  • Experience with hardware-in-the-loop testing or performance and latency evaluation for device software
  • Yocto or Buildroot experience owning the full image (distro configuration, package feeds, update integration), not limited to BSP layers
  • Open-source contributions
